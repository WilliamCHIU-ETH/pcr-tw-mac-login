### 驗證如何排除裝置依賴

查詢前確認 BlueStacks 程序與 ADB 連接埠均已停止。加密套件初始化後，禁止 Python 建立子程序，並將 ADB 路徑設為不存在的位置；再執行一次登入及查詢。四端點成功與快照一致性檢查共同支持「此執行環境能直接讀鑰匙圈查詢」的結論。

首次測試過早禁止子程序，擋住加密套件用來辨識架構的本機程序，尚未發出 API 請求。調整為套件初始化完成後才啟用禁令，才進行上述成功查詢；沒有盲目重試遊戲登入。

### 實際遇到的權限問題

寫入 BlueStacks App 內的啟動映像時，曾出現 `Operation not permitted`。本機系統紀錄指出 `SystemPolicyAppBundles` 拒絕 Terminal；輸入管理員密碼不能取代 macOS「隱私權與安全性 → App 管理」的授權。使用者授予 Terminal 該權限後重新套用，映像校驗成功。這不需要關閉 SIP，也不需要公開或傳送管理員密碼。

### 驗證邊界

這是單一主機與帳號的成功實驗，不保證鑰匙圈鎖定、執行環境變更、憑證失效或遊戲改版後仍可直接使用。查詢仍可能影響其他裝置登入。還原驗證針對啟動映像與鑰匙圈存取；不等於另做完整遊戲功能驗收。失敗時停止回報，不自動 root、不排程登入。

## 2026-10-18：原始流程紀錄

以下保留當時每次經 ADB 現讀憑證的實驗結果，不是新版鑰匙圈端到端驗證。

## 目的

把自己的角色資料交給AI分析配隊與培養方向，先成功匯出一次，之後手動更新。最低需求為角色、星數、等級、Rank及專武。

## 成功路徑

1. 在Apple Silicon Mac安裝BlueStacks Air，備份其原始啟動映像。
2. 在原始映像的官方台版遊戲內，手動完成自己帳號的引繼。
3. 在12.59GB追加下載提示取消，不先下載完整素材。
4. 完整關閉Air，再換成已校驗的root啟動映像。Android使用者資料保留。
5. 啟動Air，僅開ADB及Shell root，不啟動遊戲。讀指定App的PlayerPrefs。
6. 在記憶體解碼UDID、SHORT_UDID、VIEWER_ID及TW_SERVER_ID；檢查候選唯一性與ID一致性。
7. 由Mac Python客戶端發出一次登入／初始化流程及load/index，將unit_list中的角色欄位匯出。

本次無須關閉SIP。替換App內映像曾需要macOS的Terminal App管理權限與sudo，兩者不能混為一談；原始備份也用於黑屏診斷對照。

## 為什麼切換兩種映像

root映像下遊戲黑屏，還原原始映像後可以正常顯示。這支持環境相關性，沒有證明具體的反root檢查或某一行圖形錯誤是原因。

把正常引繼與root讀檔分開，避開了「必須在root下開遊戲」這個不必要條件。
